# AeroShell service ownership map

**Status:** T07 in progress. No service is integrated until its source/version, activation path, and real login/logout behavior are audited.

## Session chain currently implemented

User-selected display manager → /usr/bin/aeroshell-session-wayland → dbus-run-session → distro kwin_wayland --xwayland --exit-with-session → AeroShell shell-session wrapper → AeroShell Qt Quick shell. KWin also owns the session XWayland instance.

The display manager contributes the selected session and login environment. AeroShell does not invoke SDDM commands, change the default session, start startplasma-wayland or plasmashell, import variables into the persistent systemd user manager, or stop services by process name. `dbus-run-session` gives KWin and AeroShell a private session bus; the system bus remains shared. KWin receives AeroShell-only XDG configuration/data/cache/state roots. The child wrapper restores the user's original XDG roots before starting Qt/KIO and ordinary apps. The launcher currently permits KWin 6.7.4 and checks its Wayland, lifecycle, and screen-lock options before creating profile directories; fake-session fixtures check arguments, bus isolation, environment, and version rejection. A real Wayland login has not been demonstrated.

## T07 decisions still required

1. Audit the pinned portal service files and selector rules for AeroShell-specific backend selection without changing Plasma. A unique `aeroshell-portals.conf` requests GTK as the generic backend and KDE's compositor-aware backend for capture/remote desktop/input capture/global shortcuts. The launcher exports the AeroShell desktop identity to KWin and its child session, but a D-Bus/systemd-activated portal may inherit a different environment or already be running. Verify actual selection on a disposable Wayland login without importing variables into the shared user manager; do not infer runtime success from the host configuration alone.
2. Verify private-bus D-Bus activation, portal selection, and required app services without importing variables into the persistent user manager.
3. Prove tray D-BusMenu, notification, and PolicyKit interoperability; test the KScreenLocker password/unlock and resume path.
4. Determine how the display manager recovers after KWin crashes and how session runtime files are cleaned.
5. On a disposable system, exercise normal logout, shell crash, compositor crash, forced termination, AeroShell-to-Plasma switching, and safe rejection of same-user concurrent sessions.

## Hard isolation rules

- Do not use systemctl --user import-environment, dbus-update-activation-environment, or global user units until shared-manager impact and crash-independent recovery are proven.
- Do not claim a unique D-Bus name while another owner is active. Detect the owner; never kill it by name.
- Do not use startplasma-wayland, plasmashell, Plasma global defaults, SDDM KCMs, or display-manager theme/config files.
- Each session service needs an explicit parent/owner and stop action. Only terminate children recorded as started by this AeroShell session.
